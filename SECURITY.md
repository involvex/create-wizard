# Security Policy

## Supported Versions

We actively support the following versions with security updates:

| Version | Supported          |
| ------- | ------------------ |
| 4.x.x   | :white_check_mark: |
| 3.x.x   | :x:                |
| < 3.0   | :x:                |

Only the latest major version receives security patches. Please upgrade to the latest version to ensure you have the latest security fixes.

## Reporting a Vulnerability

We take security vulnerabilities seriously. If you discover a security vulnerability in this project, please report it responsibly.

### How to Report

**Please do NOT report security vulnerabilities through public GitHub issues.**

Instead, please report them via one of these channels:

1. **GitHub Security Advisories** (Preferred)
   - Go to the [Security tab](https://github.com/involvex/create-wizard/security) of this repository
   - Click "Report a vulnerability"
   - Fill in the details and submit

2. **Email**
   - Send details to: security@involvex.com
   - Include: description, steps to reproduce, impact assessment, and suggested fix (if any)

3. **Private Disclosure**
   - If you prefer encrypted communication, request our PGP key via email

### What to Include

Please provide as much information as possible:

- **Description** of the vulnerability
- **Steps to reproduce** the issue
- **Affected versions** (if known)
- **Potential impact** (what could an attacker achieve?)
- **Suggested fix** or mitigation (if you have one)
- **Your contact information** for follow-up

### Response Timeline

| Stage | Timeline |
|-------|----------|
| Initial acknowledgment | Within 48 hours |
| Triage & assessment | Within 7 days |
| Fix development | Within 30 days (critical), 90 days (high/moderate) |
| Release & disclosure | Coordinated with reporter |

We will keep you informed throughout the process and credit you in the release notes (unless you prefer anonymity).

## Security Best Practices for Users

### Keep Dependencies Updated

```bash
# Check for vulnerabilities
bun audit

# Update dependencies (patch/minor)
bun update

# Check for major updates
bun outdated
```

### Template Security

When using templates generated by create-wizard:

1. **Run `bun audit`** on generated projects periodically
2. **Enable Dependabot** on your generated repositories
3. **Monitor** the templates you use for security updates
4. **Update generated projects** when template updates are released

### CI/CD Security

The project uses:
- **Dependabot** for automated dependency updates (weekly)
- **bun audit** in CI pipeline (runs on every push)
- **njsscan** for static code analysis (weekly)
- **GitHub Code Scanning** for SARIF results

## Vulnerability Disclosure Policy

### Coordinated Disclosure

We follow coordinated vulnerability disclosure:

1. **Reporter** privately discloses vulnerability
2. **We** acknowledge, investigate, and develop fix
3. **We** agree on disclosure timeline with reporter
4. **We** release patch and publish advisory
5. **Reporter** receives credit (if desired)

### Public Disclosure

After a fix is released:
- Security advisory published on GitHub
- CVE requested if applicable
- Release notes include security fixes
- Credit given to reporter (unless anonymous requested)

### Out of Scope

The following are generally out of scope for this policy:
- Vulnerabilities in upstream dependencies (report to upstream)
- Issues requiring physical access or social engineering
- Denial of service via resource exhaustion (unless critical)
- Vulnerabilities in generated user code (not template code)
- Issues in development dependencies only (no runtime impact)
