# Plan for Creating Flutter Android App Templates

## Goal

Create two new templates in the template-library:

1. `flutter-android-app-basic`: A basic Flutter Android app with minimal setup
2. `flutter-android-app-enhanced`: An enhanced Flutter Android app with many built-in features

## Research Findings

- Existing templates follow a structure: `template-library/<name>/` with `template.json` and `files/` directory
- Some templates also use `features/` directory for conditional features (e.g., vue-wizard, discord-bot)
- Template.json defines dependencies, devDependencies, and scripts
- Files in `files/` directory are copied directly to the generated project
- No existing Flutter templates found in the library

## Implementation Plan

### 1. Basic Flutter Android App Template

**Directory:** `template-library/flutter-android-app-basic`

**Files to create:**

- `template.json`: Defines Flutter dependencies and basic scripts
- `files/`: Contains the basic Flutter project structure:
  - `android/` (Android-specific files)
  - `ios/` (iOS files - for completeness)
  - `lib/` (Dart code)
    - `main.dart` (basic Flutter app)
  - `test/` (test directory)
  - `pubspec.yaml` (Flutter project configuration)
  - `README.md` (basic project README)

### 2. Enhanced Flutter Android App Template

**Directory:** `template-library/flutter-android-app-enhanced`

**Files to create:**

- `template.json`: Defines Flutter dependencies including enhanced packages (state management, navigation, etc.) and scripts
- `files/`: Contains the enhanced Flutter project structure (similar to basic but with more features)
- `features/` (optional): For conditional features that can be toggled during template creation

**Enhanced Features to Consider:**

- State management (Provider, Riverpod, or Bloc)
- Navigation (go_router or auto_route)
- Dependency injection (get_it)
- Theming and dark mode support
- Localization (intl)
- API handling (dio or http)
- JSON serialization (json_serializable)
- Testing dependencies (mockito, flutter_test)
- Firebase integration (optional feature)
- Analytics (optional feature)
- Ads integration (optional feature)

## Implementation Steps

1. Create directory for basic template
2. Create template.json for basic template
3. Create basic Flutter project structure in files/
4. Create directory for enhanced template
5. Create template.json for enhanced template
6. Create enhanced Flutter project structure in files/
7. Optionally create features/ directory for conditional features in enhanced template
8. Verify templates work by testing with create-wizard CLI

## Notes

- Templates should follow the existing patterns in the template-library
- Use proper Flutter project structure as generated by `flutter create`
- Enhanced template should demonstrate best practices for Flutter development
- Both templates should be Android-focused but include iOS files for completeness
- README.md should explain what the template includes and how to use it
